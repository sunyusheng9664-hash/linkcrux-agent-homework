# 面试官体验流程与部署检查

## 一次体验应验证什么

用质量经理视角验证五件事：客诉是否被结构化受理；AI 是否把原文、抽取、建议与人工判断分开；知识回答是否只能引用已发布条目；高风险、低置信度或知识不足是否避免自动下结论并生成接管包；首次处理是否形成可追溯的 D1–D3 与时间表。

本地验收模式仅验证受控 Demo 流程，不代表真实模型、CloudBase 身份、数据库或对象存储已经上线。

## 面试官本地体验（无需 API Key）

在线演示优先；当网络或云环境不可用时，执行 `npm run build:offline` 后直接双击 `offline-dist/index.html`。该备用包使用 Hash 路由与内联资源，不需要本地服务或 API Key；它仅展示固定案例的 Demo 模拟，不能作为真实模型、CloudBase、RAG 或企业数据已验收的证据。

1. 安装依赖后运行 `npm run test:e2e`，或运行 `npm run dev:e2e` 并打开 `http://127.0.0.1:4173`。
2. 以默认 Demo 账号登录：`linghe` / `shuzhi`。
3. 选择“开始示例体验”，提交内置案例。
4. 在分析页核对：投诉原文、AI 抽取、待补字段、风险建议、质量经理判断彼此独立显示。
5. 在“知识核查”输入“尺寸超差后如何临时遏制？”，确认回答带有 Demo SOP、版本和分段标识；换成未覆盖问题，确认系统不补答，而是显示案件接管包。
6. 选择接受或修改建议；高风险案例必须由质量经理确认后才能继续。
7. 查看 D1–D3 初版、24h/14d/30d 交付表及 D4–D8 后续计划。所有措施均标为建议，未被表述成已执行事实。

## 线上能力与前置条件

已实现但需要部署后才能验证的链路：CloudBase 用户身份、`agent-api` 云函数、`cases`/`case_events`/`documents`/`knowledge_chunks`/`knowledge_items` 集合、对象存储附件验证、服务端模型调用。

部署前必须：

- 配置 `VITE_CLOUDBASE_ENV_ID`；
- 在云函数环境配置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`；
- 配置 `KNOWLEDGE_OWNER_USER_IDS`，仅其中用户可发布知识条目；
- 为附件存储配置仅当前用户可写入和读取的路径策略；
- 备份并迁移旧 `cases` 数据，满足 README 的版本和状态不变量；
- 确认云函数 Node 运行时符合 `package.json` 的 engines 约束；
- 不将模型密钥写入前端环境变量、仓库、日志或数据库。

## 上线后冒烟测试

1. 使用真实质量经理账号创建案件；验证跨用户案件与附件不可读取。
2. 以知识负责人上传一段文本 SOP，确认生成 `pending_review` 条目；以非负责人审核应被拒绝。
3. 发布后提问命中 SOP 的问题，确认答案附带文档/版本/分段引用。
4. 对无覆盖、敏感信息、ERP/MES 查询、高风险案件验证接管包和事件记录。
5. 检查 8D 初版没有虚构联系方式、责任、召回、赔偿或“已执行”结论。

## 本地评估基线

执行 `npm run test:eval` 可复核两组受控基线：一组覆盖普通客诉、信息不足、非品质请求、系统查询和紧急风险的路由；另一组覆盖已发布知识命中且带来源/版本、知识未覆盖、敏感请求与来源文档过期。它们用于防止后续迭代把“拒答/接管”退化为模型补全，不代表真实企业语料上的准确率指标。

## 当前已知边界

- 本地 Demo 的知识回答与接管包是确定性模拟；它验证交互和受控分流，不代表真实知识库上传、检索、模型或云端持久化。
- 文本粘贴入库可调用线上 `knowledge.ingest`；文件对象上传与生产存储策略须在 CloudBase 部署时实测。
- 只有完成上述线上冒烟测试，才可宣称线上体验已验证。
