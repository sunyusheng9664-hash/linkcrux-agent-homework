# Demo 主线案例：8D 报告样本

> 用途：给接棒 agent 做 Demo "Tab ④ 8D 报告"时直接用的填充数据。
> 案例：汽车零部件支架尺寸超差客诉。

---

## 客诉原始信息

| 字段 | 内容 |
|------|------|
| 客户 | XX 汽车零部件厂 |
| 产品 | 支架（零件号 BR-2045） |
| 批次 | 2026-W32 发货批 |
| 缺陷 | 尺寸超差（3 件） |
| 影响 | 客户产线停线 4 小时，损失约 5 万元 |
| 客户诉求 | 要求当天提交 8D 报告 |

---

## 8D 报告（Agent 自动生成草稿）

### D0 准备
- **是否启动 8D**：是。涉及客户停线 + 批量质量风险，严重度=重要，需跨部门协作。
- **紧急程度**：高（客户产线已停）

### D1 团队组建
| 角色 | 姓名 | 职责 |
|------|------|------|
| 组长 | QA 经理 | 主导分析、对外沟通 |
| 生产 | 产线主管 | 提供工艺参数 |
| 工程 | 工艺工程师 | 技术根因分析 |
| 供应链 | SQE | 供应商批次追溯 |
| 销售 | 客户经理 | 客户沟通 |

### D2 问题描述（5W2H）
| 维度 | 内容 |
|------|------|
| What | 支架 BR-2045 尺寸超差，3 件（尺寸 +0.15mm，公差 ±0.05mm） |
| When | 2026-W32 批次，客户入库检验时发现 |
| Where | 客户产线装配工位 |
| Who | 客户来料检验员发现 |
| Why（初步） | 怀疑加工刀具磨损 |
| How Many | 3/500 件 |
| How Much | 客户停线 4h，损失约 5 万元 |

**是/不是对比表：**
| 维度 | 是 | 不是 |
|------|------|------|
| 问题 | 尺寸偏大 +0.15mm | 不是外观缺陷 |
| 批次 | W32 批 | W31/W33 批正常 |
| 工序 | 精加工工序 | 不是毛坯/粗加工 |

### D3 临时遏制措施
| 措施 | 状态 | 时间 |
|------|------|------|
| 冻结厂内 W32 批库存（120 件） | ✅ 已执行 | 接诉后 2h |
| 拦截在途 2 批（80 件） | ✅ 已执行 | 接诉后 4h |
| 客户端排查（已用 50 件） | ✅ 100% 挑选 | 接诉后 6h |
| 暂停精加工工序 | ✅ 已暂停 | 接诉后 1h |

### D4 根因分析（5Why）

**发生原因（为什么会超差）：**
| 层级 | 追问 |
|------|------|
| Why 1 | 尺寸偏大 → 精加工刀具磨损 |
| Why 2 | 刀具磨损 → 使用小时超限 |
| Why 3 | 超限未换 → 更换频率未受控 |
| Why 4 | 未受控 → 控制计划缺"刀具使用小时"控制项 |
| Why 5 | 缺项 → PFMEA 未识别"刀具磨损"失效模式 |

**流出原因（为什么没拦住）：**
| 层级 | 追问 |
|------|------|
| Why 1 | 超差件流出 → 终检未检出 |
| Why 2 | 未检出 → 终检抽检而非全检 |
| Why 3 | 抽检 → 该工序 Cpk=1.1，风险等级判定为"可抽检" |

**根因结论：** 发生根因=PFMEA 缺刀具磨损失效模式；流出根因=Cpk 判定风险等级偏低。

### D5 永久对策
| 对策 | 负责人 | 类型 |
|------|--------|------|
| 更新 PFMEA，增加"刀具磨损"失效模式 | 工程 | 防错 |
| 控制计划增加"刀具使用小时"控制项 | 质量 | 防错 |
| 制定刀具更换 SOP（每 2000 件强制换刀） | 生产 | 标准化 |
| 建立刀具使用日志系统 | 设备 | 系统 |
| 精加工工序 Cpk 重新评估，调整抽检比例 | 质量 | 验证 |

### D6 验证实施
- 小批量试产 3 批（每批 100 件），尺寸全部合格
- 试产期间 SPC 监控，Cpk 从 1.1 提升至 1.67
- 客户确认接受

### D7 预防再发（横向展开）
| 展开范围 | 动作 |
|---------|------|
| 同类产品 | 排查所有精加工工序，更新 PFMEA |
| 同类产线 | 2 号线、3 号线同步加刀具控制 |
| 管理体系 | 更新控制计划模板，新增"刀具类"必检项 |
| 培训 | 纳入新员工质量培训材料 |

### D8 总结沉淀
- 8D 报告归档入知识库
- 案例分享至全厂质量月会
- 团队表彰

## Agent 归因打标（关键差异化）

| 维度 | 结果 |
|------|------|
| 是否首次发生 | ❌ 否 |
| 历史频次 | 3 个月内第 3 次出现"支架尺寸超差" |
| 归因类型 | 反复出现 → 根因未闭环 |
| 建议动作 | 触发横向排查，而非仅处理本单 |
| 推送对象 | 研发部门 + 质量总监 |

> **Agent 的核心价值体现**：如果只是处理这一单，3 个月后还会第 4 次。归因打标把"反复出现"这个信号识别出来，推给研发做系统性改进——这才是"客诉闭环"而非"客诉处理"。
