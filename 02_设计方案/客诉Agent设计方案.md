# 制造业客诉处理 Agent 设计方案

> 作业交付物 · 主文档
> 定位：面向非技术背景负责人的、轻量但完整的 Agent 设计方案
> 作者视角：懂业务 + 能把 AI 落地的产品人

---

## 0. 一页看懂这个 Agent

**一句话定位：**

> 一个帮制造业工厂"接、判、分、回、追"客诉的 AI 数智员工——它让每一个客诉客户都被**认真对待、有明确预期、有可信交代**，把客诉处理从"小时级"压到"分钟级"。

**核心立场（客户体验为主视角）：**

这个 Agent 的第一优先级，不是"帮工厂省人力"，而是**"让客户在处理过程中始终感到确定、被重视、不被踢皮球"**。因为制造业 B 端客户的产线在等你，他要的不是客气的语气，而是三个东西：

1. **确定性**：24h 内必响应，明确告诉他"现在走到哪一步、什么时候给结果"。
2. **不被踢皮球**：一次说清，后面有人盯到底，不用对着不同部门重复三遍问题。
3. **有交代**：最终给他一份可信的根因和对策（8D 报告），而不仅是"收到，我们会处理"。

**它不是什么：**
- ❌ 不是"只会聊天的智能客服"（只答复、不闭环）
- ✅ 是"能接管客诉处理一段真实工作流、让客户全程有感知、最终给专业交代的岗位级数智员工"

---

## 1. 为什么是"客诉处理"这个岗位

（对齐灵核数智的产品哲学）

1. **入口级场景**：客诉是"离客户最近、离钱最近"的入口，符合"入口级 Agent 优先落地"的判断。
2. **高重复 + 强规则**：客诉处理的登记、分类、分派、追溯是高度重复且规则相对明确的流程，最适合 Agent 化。
3. **天然闭环**：客诉天然有"响应→调查→对策→关闭"的闭环结构，Agent 的价值能被量化（响应时长、闭环率、归因准确率）。
4. **知识沉淀刚需**：每一次客诉的根因都是企业最值钱的隐性知识，Agent 能把它显性化、结构化、可复用（呼应"721 理论"中的 20% 人机交互沉淀）。

---

## 2. 核心方法论：五字主流程

**接 → 判 → 分 → 回 → 追**

这五个字是整个 Agent 的骨架，也是面试时可以反复强调的"方法论标签"。**每一步都同时有"内部动作"和"客户感知"两个维度**——内部跑流程，外部让客户有感知，这是"客户体验"落地的核心机制。

```
接：多模态受理（文字/图片/语音/批次号 OCR）
  │   → 客户感知：我说一遍就够了，不用重复描述
  ↓
判：意图理解 + 客诉分类 + 紧急度评分 + 触发 SLA 计时
  │   → 客户感知：系统立刻判断出这事有多急、谁来管
  ↓
分：按类型/区域/产线自动分派到对应角色，必要时人工兜底
  │   → 客户感知：我不会被踢皮球，有专人盯到底
  ↓
回：分阶段客户触达（受理确认 → 进展同步 → 结果交代）+ 内部工单
  │   → 客户感知：全程有明确预期，每个时间节点都有回应
  ↓
追：调知识库初判根因 + 归因打标（首次/反复）+ 触发 8D 报告
      → 客户感知：最终拿到一份可信的根因与对策交代
```

**为什么是这五个字，而不是"一个对话框"？**

因为客诉处理本质是一个**流程**，不是一个**对话**。客户的诉求是"给我一个结果"，不是"跟我聊下去"。五字主流程把"结果导向"固化成了 Agent 的工作方式——**而"客户感知"这一列，就是"结果导向"从客户视角的体现**。

## 3. 分层架构（给非技术人看的一张图）

```
┌─────────────────────────────────────────────────┐
│  感知层：客户接入                                  │
│  （企业微信 / 邮件 / 拍照上传 / 电话录音转写）       │
└────────────────────┬────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────┐
│  决策层：五字主流程（Agent 大脑）                   │
│   接 → 判 → 分 → 回 → 追                          │
│   （理解 + 分类 + 调度 + 生成 + 归因）             │
└────────────┬───────────────────┬─────────────────┘
             ▼                   ▼
┌──────────────────────┐  ┌──────────────────────┐
│  知识层：行业知识 + 历史档案 │  │  执行层：工单/ERP/MES/8D   │
│  （8D/SOP/根因库/产品工艺） │  │  （生成工单、查批次、出报告）│
└──────────────────────┘  └──────────────────────┘
                     ▼
┌─────────────────────────────────────────────────┐
│  人工闸口：Human-in-the-loop                       │
│  （召回决策、对外回复、责任判定 必须人审核）         │
└─────────────────────────────────────────────────┘
```

**这张图要传达的核心信息：**
1. 客户进来，Agent 跑流程，最后有人兜底——不是"AI 说了算"，是"AI 干活、人做判断"。
2. 知识层和执行层是 Agent 的"记忆"和"双手"，让它不只是会说话。
3. "人工闸口"是产品态度：客诉涉及对外承诺，必须可信。

## 4. 五步详解（每一步的"为什么"）

### 4.1 接——多模态受理

| 能力 | 说明 |
|------|------|
| 文字受理 | 客户在微信/邮件里描述问题 |
| 图片受理 | 客户拍缺陷照片、产品标签 → OCR 识别批次号/序列号 |
| 语音转写 | 电话录音 → 文本 |
| 结构化抽取 | 从零散描述里自动抽出：产品、批次、缺陷现象、发生时间、影响数量 |

**为什么要有"接"：** 客诉第一手信息往往是非结构化的（一段语音、一张照片、几句抱怨）。Agent 的第一个价值就是把"非结构化"变成"结构化"，这是后续一切判断的基础。**入口端不能出错**（呼应"入口级 Agent 输入端不能出错"）。

### 4.2 判——分类 + 紧急度 + SLA

| 判断维度 | 内容 |
|----------|------|
| 客诉类型 | 来料不良 / 过程异常 / 交付延期 / 批次质量 / 退换货 / 客户体验 |
| 严重度 | 一般 / 重要 / 严重（安全/召回/合规 → 必须升级） |
| 紧急度评分 | 综合"客户等级 + 影响面 + 安全风险"打分 |
| SLA 计时 | 触发"24h 响应"倒计时 |

**为什么要有"判"：** 客诉不能"一刀切"。一个批量安全隐患和一个外观瑕疵，处理方式完全不同。判的作用是**决定"谁来管、多快管、怎么管"**，这是 Agent 从"聊天"升级到"调度"的关键一步。

### 4.3 分——自动分派

- 按客诉类型分派到对应角色（质量/研发/供应链/销售）
- 按区域/产线/品类路由
- **置信度低于阈值 → 自动转人工**（不硬判）

**为什么要有"分"：** 分派是"执行"的开始。传统模式下，客诉在部门间"踢皮球"是最耗时的环节。Agent 的价值是把"该谁处理"这个决策前置、自动化、可追溯。

### 4.4 回——分阶段客户触达（客户体验的核心触点）

| 阶段 | 对象 | 内容 | 客户体验价值 |
|------|------|------|-------------|
| 受理确认 | 客户 | 立即回"已收到，正在处理"，给出响应时限承诺 | 确定性：第一时间消除"你收到没有"的焦虑 |
| 进展同步 | 客户 | 关键节点主动同步（已分派/已定位根因/已出对策） | 不被晾着：全程有感知，不用追问 |
| 结果交代 | 客户 | 给出根因 + 对策 + 预防（8D 报告） | 有交代：拿到可信结果，而非客套话 |
| 内部工单 | 内部 | 结构化字段（产品/批次/缺陷/紧急度/分派对象/SLA） | 支撑上述触达不掉链子 |

**为什么要有"回"：** 这是"先处理心情再处理事情"的落地。制造业客户最在意的不是"立刻解决"，而是"你重视我、给我明确时间表、最终给我交代"。

**关键设计：客户触达不是"一次回复"，而是"三段式"** —— 受理确认（秒级）→ 进展同步（关键节点）→ 结果交代（闭环）。这让"回"从单个动作，升级为一个贯穿全流程的**客户体验主线**。

### 4.5 追——归因 + 8D（核心差异化）

| 动作 | 说明 |
|------|------|
| 根因初判 | 调历史客诉知识库，匹配相似案例的根因 |
| 归因打标 | **"这是第一次发生，还是反复出现？"** ← 灵核强调的差异化 |
| 全链路追溯 | 批次 → 工单 → 工艺参数 → 供应商批次 |
| 8D 报告生成 | 自动产出 D1-D8 报告草稿，人工确认 |
| 经验入库 | 闭环后，根因和对策沉淀进知识库 |

**为什么要有"追"：** 这是客诉 Agent 和"智能客服"的**分水岭**。智能客服止步于"回答"，客诉 Agent 走到"归因 + 改进"。追这一步，把"单个客诉事件"转化成了"企业质量能力提升"的资产。

## 5. 关键设计决策（面试加分项：展示"思考"）

**决策 1：把"判"和"分"拆成两步，而不是一步"智能分流"**
- 理由：判是"理解"（这件事是什么、多严重），分是"执行"（谁来管）。拆开才能让每一步可观测、可单独调优。如果合在一起，出错时无法定位是"理解错了"还是"派错了"。

**决策 2：必须有人工闸口（Human-in-the-loop），而非全自动**
- 理由：客诉涉及对外回复、召回决策、责任判定——这些是"高风险动作"，AI 不能独断。设计原则是"AI 干活、人做判断"（呼应陈弘旋"让人变成判断容器"）。

**决策 3：把 8D 报告做成"自动生成"，而非"模板填空"**
- 理由：8D 是制造业最认的"行业语言"。Agent 能自动产出 8D 草稿，证明它"懂制造"，而不是通用聊天机器人。这是最强的能力证明。

**决策 4：归因打标（首次 vs 反复）是核心价值，而非附加功能**
- 理由：单次客诉是事件，归因后的"反复出现"是信号。区分"首次/反复"，决定是"正常处理"还是"触发横向排查"，这是把客诉转化为质量改进的关键。这是灵核数智公开强调的方向，方案与之对齐。

**决策 5：知识库是"边用边沉淀"，而非"先建好再用"**
- 理由：对齐"721 理论"——20% 价值来自人与 Agent 的交互沉淀。Agent 在每次处理中自动把"新根因、新对策"入库，知识库越用越值钱，形成飞轮。

**决策 6：给客户一个"进度看板"，让客诉全程透明**
- 理由：客户体验的第一杀手是"不确定性"。一个实时进度看板（受理→分派→根因→对策→关闭），让客户随时能看到自己的客诉走到哪一步，从"被动追问"变成"主动感知"。这是把"客户体验"从口号变成产品的关键动作。

## 6. 一个完整案例走查（Demo 主线）

**场景：** 某汽车零部件厂收到客户投诉——

> 客户语音："你们上周发的那批支架，装到我们产线上有三件尺寸超差，我们停了 4 小时，损失大概 5 万，今天下班前要你们的 8D 报告。"

**Agent 处理全流程：**

| 步骤 | Agent 动作 | 展示价值 |
|------|-----------|---------|
| 接 | 语音转写 → 抽取：产品=支架、批次=上周发货、缺陷=尺寸超差、影响=停线4h | 多模态结构化 |
| 判 | 分类=过程异常；严重度=重要；紧急度=高（停线）；SLA 启动 | 智能分级 |
| 分 | 分派给 QA（质量），同步抄送销售 | 自动分派 |
| 回 | 客户回复："已收到，正在紧急处理，24h 内给初步结论" + 生成内部工单 | 双输出 |
| 追 | 查历史库 → 匹配"支架尺寸超差"根因 → 归因打标：**反复出现（第3次）** → 触发 8D + 横向排查建议 | 归因 + 8D |

**最后呈现：** 一份自动生成的 8D 报告草稿 + 一条"该问题 3 个月内第 3 次出现，建议横向排查同类产线"的改进建议。

> 这个案例的杀伤力在于：**它演示了 Agent 如何把"一个客户投诉"变成"一次质量体系改进"**，这正是灵核数智"客诉闭环"理念的具象化。

## 7. Demo 产品形态（轻量但完整）

| Tab | 内容 | 目的 |

## 8. 价值量化（面试讲 ROI 用）

| 指标 | 传统方式 | Agent 后 | 客户体验价值 |
|------|---------|---------|-------------|
| 客诉响应时长 | 数小时~48h | 分钟级（24h 内必响应） | 确定性 |
| 登记+分类+分派 | 30-60 分钟/单 | 秒级 | 不被踢皮球 |
| 全链路追溯 | 2-3 小时 | 分钟级 | 结果更快 |
| 8D 报告编写 | 数小时~数天 | 自动生成草稿+人工确认 | 有可信交代 |
| 客户追问次数 | 多次（不知进展） | 近零（看板透明） | 不被晾着 |

## 9. 落地路径（三步走）

| 阶段 | 内容 | 周期 |
|------|------|------|
| MVP | 单个工厂 + 单个产品线，跑通"接判分回追"闭环 | 2-4 周 |
| 试点 | 扩到全品类，接入 ERP/MES，打通追溯 | 1-3 个月 |
| 全量 | 多工厂、多客户，知识库沉淀成企业质量资产 | 3-6 个月 |

> 呼应灵核"7-15 天上线、先跑通一个岗位"的落地节奏。

## 10. 一句话总结（面试收尾金句）

> "这个 Agent 不是让 AI 去当客服，而是让 AI 去当质量员——它让客户说一遍就够、全程看得见进展、最后拿到一份可信的交代。客户要的是'被认真对待'，企业要的是'改进能力'，这个 Agent 用一套流程同时给到这两样。"
